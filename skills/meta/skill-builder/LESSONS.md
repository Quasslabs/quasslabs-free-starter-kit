# Lessons Learned — skill-builder

| Lesson | Why it matters | Source |
|---|---|---|
| Separate planning, execution, and verification outputs. | The skill is useful only when a later agent can see what changed and how it was checked. | SKILL.md workflow |
| Extract deterministic helpers before calling AI for skill-builder. | Parsing, validation, routing, and manifests are cheaper and safer as pure functions. | FUNCTIONS.md classification |
| Make handoffs explicit instead of relying on chat context. | Downstream skills and agents need paths, payloads, and auth assumptions recorded in files. | SKILL.md handoffs |
| skill-builder + simplify chained = clean iterative edits. | Running simplify after each targeted skill-builder edit kept adjacent code intact and diffs small. Iterative > big-bang rewrites. | 2026-05-08 session |
| Drafting prompts for a different Claude agent is a first-class use case. | Human-in-the-middle pattern (craft prompt → paste to other agent → review result) recurred enough to formalize as agent-prompt-crafter skill. | 2026-05-08 session |

## Draft-from-source scaffolder (draft_skill.py, 2026-05-25)
- Origin: `virgiliojr94/book-to-skill` (MIT) pattern — source doc → first-draft skill.
- **Sprawl guard is the whole design:** always `Status: draft`, written to `wip/<name>/`, NEVER registered/promoted; forces Status:draft via regex even if the model emits otherwise; refuses to overwrite. Human must review + lint + promote.
- **Use `qwen2.5-coder:14b` (task_type='code'), NOT the 32B:** template-filling timed out on qwen2.5:32b at 240s (large-prompt cold-load); the 14B coder loads + responds faster and is plenty for structured fill.
